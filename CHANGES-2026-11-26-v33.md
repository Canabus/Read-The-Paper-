## Nate-approved feature — trigger date for relative deadlines

Approved by Nate explicitly (his yes, 2026-11-26) — this is authorized product
direction, not a reviewer suggestion. Everything else in v33 is unchanged from
v32; Books mode untouched.

**What the user sees, no trigger date entered (the default):** exactly v32.
Relative windows ("within 30 days", "grace period of 15 days", renewals) sit at
the bottom of the timeline labeled "· relative — no calendar date in the
document", and the date-confirmation list contains only dates detected in the
text. The app never guesses an anchor — not from a document date, not from a
detected signing date, not from today.

**What the user sees with a trigger date entered:** the timeline section has a
date input labeled "When did the clock start? (optional)" with a plain helper
line (signing date, notice date, statement date — whatever day the document
counts from; leave it blank and the windows stay relative, the way the document
wrote them). Entering a date re-runs the timeline and the confirmation list for
the current reading, no re-upload. Each relative window whose count reads as a
plain number of days ("within 30 days", "grace period of 15 days", "within 10
days", "no later than 30 days", "after 10 days", cure windows in days) then
shows, next to the clause's own unchanged verbatim words: "≈ Dec 30, 2026 —
counted from the start date you entered". The ≈ and the counted-from label are
always present — a counted date never reads as a date the document stated, and
it never appears inside document quotes, findings, or verbatim passages.
Windows that cannot be read as a plain day count stay relative even with a
trigger entered: month/year windows, renewals, "at least N days before",
"more than N days" — never guessed. (The "at least … before" family counts
backwards from an event rather than forward from a start date, so it is
deliberately left unanchored in this version.)

**Calendar export:** counted dates join the existing date-confirmation list,
flagged as calculated, with the meaning preset to "Counted from the start date
you entered" (the only other option being "Not a deadline / not established",
which still excludes them). They export only when ticked, like every other
date, and the .ics SUMMARY/DESCRIPTION carries the counted-from wording — a
counted date is never exported as if the document stated it. All v32 ICS
behavior (RFC 5545 escaping, 75-octet folding, charset=utf-8, content-hash
UIDs) applies unchanged.

**State:** the trigger date lives in one in-memory variable with the current
reading — no storage key added, nothing written to localStorage/sessionStorage.
It is cleared by a new reading, the Clear button, packet-removal reading
clear, and the wipe control.

**Fixtures (T-series, all passing):** relDaysFor reads plain day counts and
refuses months/renewals/at-least-before; blank trigger reproduces v32 labels
with no ≈ anywhere; trigger Nov 30, 2026 → "within 30 days" = ≈ Dec 30, 2026,
"grace period of 15 days" = ≈ Dec 15, 2026, "within 10 days" = ≈ Dec 10, 2026
(exactly three counted labels; month window and renewal stay relative);
verbatim sentences unchanged beside the counted dates; no ≈ or counted-from
text in findings/quotes sections; confirmation list gains the three calculated
entries flagged `calculated`; the .ics export of a ticked counted date carries
the counted-from wording; month-boundary arithmetic Jan 30 + 15 days = Feb 14,
2027; a new reading clears the trigger back to null.
