## Fixes

| # | Defect (verification verdict) | Fix |
|---|-------|-----|
| 1 | **Page-marker forgery — CONFIRMED, the review's FAIL.** `packetCombinedText` converted anchored `[Page N]` into genuine `⟦RTP·PG·⟧` markers in EVERY packet entry, so a .txt or pasted entry whose line begins `[Page 12] ` earned real page credit; single-document `pageOf` counted any `[Page N]` anywhere in pasted text. | Packet entries now record their origin (`pdf` / `ocr` / `text` / `paste`) when filled in `handleFiles` / `packetAddText`. The conversion runs ONLY for pdf/ocr-origin entries; for text/paste entries the anchored form is document prose and is neutralized like other body literals. Single-document `pageOf` counts `[Page N]` only when the reading's origin is PDF extraction — an origin flag is threaded from every analyze/analyzeTrust caller (paste → `paste`, samples → `text`, packet → `packet`, default `unknown`) — and fails closed otherwise. PDF packet readings keep working page numbers (fixture 1b: p. 1 / p. 2 credited correctly). |
| 2 | **Loose-probe page credit — CONFIRMED.** In single-document mode, `findNeedleIndex`'s prefix probes (120/60/30 chars) and 4-word fallback could locate a passage, and `pageOf` would print a page number next to the "· verbatim ·" tag for a quote that never matched in full. | Loose probes still locate a quote for display, but a new `fullNeedleIndex` (full needle only, occurrence-counted) gates both the page number in `pageOf` and the "· verbatim ·" tag, now emitted via a `verbatimSep()` helper at the three instrument-check call sites. Prefix/word-fallback matches resolve to "location not available" and a plain separator. Packet mode unchanged (already full-needle only). |
| 3 | **Section 5 false all-clear — CONFIRMED.** "Found" is a single regex sentence match; the ratecap regex's bare `usury` alternative matched any mention of the word, and the all-found message asserted "Every clause on the … checklist was found." | (a) Bare `usury` dropped from the ratecap regex — usury now matches only with a law/limit/cap/ceiling context word (singular, word-bounded) or within 40 chars of "not exceed / limited to / maximum". (b) Both all-found messages in `renderMissingClauses` now use detection language: "Every item on the … checklist matched something in what you gave it," followed by the existing detection-not-verification sentence (the type-specific branch adds: a match means wording on the item's topic was detected, not that a clause with that effect is present). Three-state structure and per-item questions untouched. |
| 4 | **Hash comment overclaims — CONFIRMED.** Comments called the 32-bit djb2 packet token "collision-proof" (two places), and the ICS UID comment claimed two different dates "never" share a UID. | Comments only, no behavior change: "collision-proof" removed (now "token-carrying"), and the UID comment states it is a 32-bit content hash and collisions are unlikely, not impossible. |
| 5 | **cleanStore bad IDs / notice values — CONFIRMED.** Entries with a missing or non-string id passed validation untouched and skipped duplicate detection; a non-plain-object notice value inside a bill's `notices` was left as-is. | In both the bills and reports branches, a missing/non-string id now drops the entry and counts it as damaged. In the bills branch, a notice value that is not a plain object is replaced with a blank `{sent:'', reply:'', status:''}` notice. |
| 6 | **curelen couldn't-check duplication — CONFIRMED.** `computeMissingClauses` suppressed `curelen` in the not-found list and in `uncheckedItems`, but the couldn't-check (reasons) return built its list from unfiltered `allItems`, so "Cure period length" appeared as its own couldn't-check row — the same gap reported twice. | The reasons-path return filters `curelen` out of `allItems`, mirroring the other two suppressions. |
| 7 | **buildTimeline dedupe collapse — CONFIRMED.** Both `seenEv` keys were the matched phrase + the sentence's first 40 characters, so two distinct sentences sharing a date phrase and a 40-char opening silently collapsed into one timeline entry. | Both keys now use the phrase + the full sentence's length + a djb2 hash of the full sentence. Distinct same-prefix sentences both appear; exact duplicate sentences still dedupe (fixtures cover both the date-event and relative-window paths). |
| 8 | **Partial items, cheap hardening.** (a) `handleFiles` OCR/PDF chains had no `.catch` (PARTIALLY CONFIRMED — the helpers resolve null on ordinary failures; only a synchronous throw could strand a packet entry). (b) The packet remove handler's name-based `FILE_HASHES` fallback (PARTIALLY CONFIRMED — unreachable in v35, but a wrong-file splice if it ever ran). (c) Remove/move handlers left `LAST_DEADLINES`/`LAST_MISSING`/`LAST_CLAIM_RECORD` set after clearing the reading (PARTIALLY CONFIRMED — stale state, export unreachable while results hidden). (d) `fingerprintReading`'s async text digest had no run guard (PARTIALLY CONFIRMED — a rapid re-run race could append a stale fingerprint segment). | (a) `.catch` added to both chains: fills the entry with the existing could-not-be-read note wording and calls `done()`. (d) A `FINGERPRINT_RUN` run token guards both the digest `.then` and `.catch` appends. |
