# Read the Paper — v37 (2026-11-28)

One verified bug fix and three small display fixes. Nothing else changed; Books mode untouched.

## The fix: validation letters were addressed to the wrong party

Every letter shared one "send to" field, and the Who/Where analysis pre-filled it with the **servicer**. The validation letter is an FDCPA letter — it demands verification from a **debt collector** — so a reading that named both a servicer and a collector produced a validation letter headed to the servicer unless the user noticed and retyped it.

Now:
- Who/Where also remembers the collector and creditor it finds.
- The validation letter builds its own header: the collector's name when the document named one, and the validation-purpose address (the "send dispute / error notice / validation here" address) when the document printed one and the user hasn't typed an address.
- If the user types a recipient themselves, that entry is used for every letter and is never overridden.
- The dispute and affidavit letters are unchanged — the servicer default was already correct for them.
- Edge case: after a page reload, a restored recipient is treated as the user's own entry until a fresh Who/Where run, so the validation letter falls back to the shared recipient rather than guessing.

## Display fixes

- **iPhone zoom:** on small screens, form fields now render at 16px so iOS Safari no longer auto-zooms when a field is tapped. Desktop sizes unchanged.
- **Anchor offset:** sections and cards carry a scroll margin so jumped-to headings no longer slide under the tab bar.
- **Printing:** a print stylesheet hides the app chrome and prints letters and templates black on white, full width — letters are the part worth mailing, so they print clean.
