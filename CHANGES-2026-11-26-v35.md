## Per-claim verdicts

| # | Claim | Verdict |
|---|-------|---------|
| 1 | Restore removes on-device stores the backup doesn't name (full-replace), but the success message never names a cleared store — silent data loss under a "restored" message | **VERIFIED + FIXED (message only).** Full-replace behavior is unchanged and deliberate (the backup pane documents the backup as the complete on-device state). The result message now names any store the backup didn't include that held on-device data and was cleared to match the backup, so nothing is cleared silently. |
| 2 | The 500-entry cap's drops are counted in the same `droppedTotal` as genuinely damaged entries, and the restore message calls all of them "damaged" | **VERIFIED + FIXED.** Capped drops are now counted separately, and the message says they were "left out over the 500-entry size limit — they weren't damaged," distinct from the damaged-entry count. |
| 3 | Definitions guard checks only the term (`m[1]`) against the text, not the assembled reconstructed quote, so a malformed reconstruction can yield a definition card with no page | **VERIFIED + FIXED.** The guard now verifies the assembled quote against the collapsed text before the card is rendered with a location. |
| 4 | `uncheckedItems` populates only when the document type is unidentified; on an identified lease or loan, the other checklists vanish silently — never shown as unchecked | **VERIFIED + FIXED.** When a type IS identified, one plain line under a Couldn't-check heading names the checklists that weren't run for that document type. The v32 itemization for unidentified types is unchanged. |
| 5 | Bills `cleanStore` never constrains `type` — a value other than `cell`/`medical` passes validation and survives the save/restore round trip | **VERIFIED + FIXED.** A bill whose `type` is present, non-null, and not `cell` or `medical` is now dropped and counted as damaged, consistent with the existing `amount`/`category` rules. |
| 6 | `__proto__` key loss in the Who/Where tracker cleaner: `out[key] = val` sets the prototype instead of an own property when the key is literally `__proto__`, so the entry round-trips once and disappears on re-serialize | **VERIFIED + FIXED.** The `__proto__` key is skipped and counted as dropped; no prototype pollution, no silent loss. |
| 7 | A page marker at the very end of a file's text demotes: `packetCombinedText` converts only anchored `[Page N] ` with a trailing space, so a marker as the last characters of a file stops counting as a page | **VERIFIED + FIXED.** End-of-string is now a valid anchor terminator alongside the trailing space. |
| 8 | Wipe-all clears storage but leaves `LAST_DEADLINES`, `LAST_MISSING`, and `LAST_CLAIM_RECORD` in memory | **VERIFIED + FIXED.** All three are reset in the wipe handler, like everything else the wipe clears. |
| 9 | `extractEntityNear` is called with a second argument its one-parameter signature ignores | **VERIFIED + FIXED.** The dead argument is removed at the call site. No behavior change. |
| 10 | A pasted-text packet entry gets no hash slot and never appears on the fingerprint line, with no explanation of why | **VERIFIED + FIXED.** When a pasted entry with text is present, the fingerprint line now notes: "Pasted text has no file fingerprint — it was pasted in, not added as a file." |
